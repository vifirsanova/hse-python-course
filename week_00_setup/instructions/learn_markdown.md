# Markdown и README

## Что такое Markdown

Markdown — простой язык разметки текста. Файлы Markdown обычно имеют расширение `.md`.

На GitHub Markdown используется для:

- README;
- описания проектов;
- инструкций;
- отчётов;
- комментариев;
- задач и pull request.

Markdown нужен, чтобы обычный текст отображался структурированно и был удобен для чтения.

---

## Зачем нужен README

`README.md` — это главная страница репозитория.

По README пользователь должен быстро понять:

- что находится в репозитории;
- для чего нужен проект;
- как его установить;
- как его запустить;
- как проверить результат;
- кто автор проекта.

README — лицо репозитория. Даже хороший код трудно оценить, если непонятно, что он делает и как его запустить.

---

## Основные правила оформления

### Заголовки

Для заголовков используются символы `#`.

```md
# Название проекта

## Установка

### Запуск
```

Используйте один заголовок первого уровня — название проекта.

Не перескакивайте через уровни:

```md
# Проект
## Установка
### Windows
### macOS
## Запуск
```

---

### Абзацы

Отделяйте абзацы пустой строкой:

```md
Первый абзац.

Второй абзац.
```

Не пишите весь README одним большим текстом.

---

### Жирный и курсивный текст

```md
**важная информация**

*дополнительное пояснение*

***жирный курсив***
```

Не выделяйте жирным весь текст. Выделяйте только ключевые слова и предупреждения.

---

### Списки

Маркированный список:

```md
- первый пункт
- второй пункт
- третий пункт
```

Нумерованный список:

```md
1. Скачайте проект.
2. Установите зависимости.
3. Запустите тесты.
```

Для последовательности действий используйте нумерованный список.

---

### Ссылки

```md
[Официальный сайт Python](https://www.python.org/)
```

Текст ссылки должен объяснять, куда она ведёт.

Плохо:

```md
[ссылка](https://www.python.org/)
```

Хорошо:

```md
[Скачать Python](https://www.python.org/downloads/)
```

---

### Код в строке

Для коротких команд и названий файлов используйте обратные кавычки:

```md
Запустите команду `pytest`.
```

Результат:

Запустите команду `pytest`.

---

### Блоки кода

Для команд и программ используйте блоки кода с указанием языка:

````md
```bash
pip install -r requirements.txt
pytest -v
```
````

Для Python:

````md
```python
def hello():
    print("Hello")
```
````

Указание языка добавляет подсветку синтаксиса и делает код понятнее.

---

### Изображения

```md
![Описание изображения](https://example.com/image.png)
```

Описание в квадратных скобках должно объяснять содержание изображения.

---

### Цитаты и предупреждения

```md
> Важно: перед запуском тестов установите зависимости.
```

Используйте цитаты для важных замечаний, ограничений и предупреждений.

---

### Таблицы

Таблицы подходят для небольшого количества структурированных данных:

```md
| Команда | Назначение |
| --- | --- |
| `git status` | Показать состояние репозитория |
| `git add .` | Подготовить изменения |
| `git push` | Отправить изменения на GitHub |
```

Не используйте таблицы для длинного текста или последовательности действий.

---

### Чек-листы

```md
- [ ] Установить Git
- [ ] Склонировать репозиторий
- [ ] Установить зависимости
- [ ] Запустить тесты
```

Чек-лист удобен для списка задач.

## Структура README проекта

Для учебного проекта используйте следующую структуру:

```md
# Название проекта

Краткое описание проекта в одном-двух предложениях.

## Содержание

- [Установка](#установка)
- [Запуск](#запуск)
- [Структура проекта](#структура-проекта)
- [Автор](#автор)

## Установка

```bash
git clone https://github.com/USERNAME/REPOSITORY.git
cd REPOSITORY
pip install -r requirements.txt
```

## Запуск

```bash
pytest seminar*/tests/ -v
```

## Структура проекта

```text
project/
├── seminar1/
│   ├── tasks/
│   └── tests/
├── requirements.txt
└── README.md
```

## Автор

Имя Фамилия, группа.
```

---

## Правила хорошего README

1. Начинайте с названия проекта.
2. Сразу объясняйте назначение проекта.
3. Пишите короткими абзацами.
4. Используйте заголовки и списки.
5. Команды оформляйте блоками кода.
6. Указывайте порядок установки и запуска.
7. Проверяйте, что ссылки работают.
8. Не оставляйте шаблонные placeholders:
   - `YOUR-USERNAME`;
   - `[Ваше имя]`;
   - `[Описание проекта]`.
9. Не добавляйте лишнюю теорию.
10. Перед сдачей откройте README на GitHub и проверьте, как он отображается.
