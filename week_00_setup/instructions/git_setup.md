# Git: установка и первая отправка проекта на GitHub

Git — система контроля версий. Она сохраняет историю изменений файлов, а GitHub позволяет хранить Git-репозитории в интернете.

Цель инструкции — установить Git, настроить его и отправить первый коммит в GitHub-репозиторий из командной строки.

---

## 1. Установка Git

### Проверка установленного Git

Откройте терминал:

- Windows — **Git Bash** или PowerShell;
- macOS — приложение **Terminal**;
- Linux — любой терминал.

Выполните:

```bash
git --version
```

Если Git установлен, появится его версия. Если система сообщает, что команда не найдена, установите Git одним из способов ниже.

---

## Windows

### Способ 1. Установщик Git for Windows

1. Откройте страницу загрузки:  
   https://git-scm.com/install/windows
2. Скачайте установщик для своей системы:
   - x64 — большинство современных компьютеров;
   - ARM64 — компьютеры на ARM-процессорах.
3. Запустите установщик.
4. В процессе установки оставьте настройки по умолчанию.
5. После установки откройте **Git Bash**.
6. Проверьте установку:

```bash
git --version
```

Git Bash — терминал, который устанавливается вместе с Git for Windows и позволяет использовать команды Git в Unix-подобном формате.

### Способ 2. Через winget

Если в Windows доступен пакетный менеджер `winget`, выполните в PowerShell:

```powershell
winget install --id Git.Git -e --source winget
```

После установки закройте и снова откройте терминал.

## macOS

### Способ 1. Xcode Command Line Tools

Откройте Terminal и выполните:

```bash
git --version
```

Если Git отсутствует, macOS предложит установить Command Line Tools. Подтвердите установку и дождитесь её завершения.

### Способ 2. Установщик Git

1. Откройте страницу:  
   https://git-scm.com/install/mac
2. Скачайте установщик.
3. Установите Git, следуя инструкциям.
4. Проверьте установку:

```bash
git --version
```

### Способ 3. Homebrew

Если у вас установлен Homebrew:

```bash
brew install git
```

Проверка:

```bash
git --version
```

## 2. Первичная настройка Git

Git записывает имя и электронную почту автора каждого коммита. Эти данные нужно настроить один раз.

Используйте имя, под которым вы хотите отображаться в истории коммитов:

```bash
git config --global user.name "Имя пользователя"
```

Укажите адрес электронной почты:

```bash
git config --global user.email "your-email@example.com"
```

Проверьте настройки:

```bash
git config --global --list
```

Ожидаемые параметры:

```text
user.name=Имя пользователя
user.email=your-email@example.com
```

Желательно использовать тот же адрес электронной почты, который привязан к вашему аккаунту GitHub.

## 3. Создание репозитория на GitHub

1. Войдите в свой аккаунт на https://github.com
2. Нажмите **New repository**.
3. Введите название репозитория, например:

```text
python-course-surname
```

4. Выберите вид репозитория:
   - **Private**, если репозиторий должен быть доступен только вам и преподавателю;
   - **Public**, если преподаватель указал сделать его открытым.
5. Не добавляйте README на этом шаге.
6. Нажмите **Create repository**.

После создания GitHub покажет адрес репозитория. Он будет выглядеть примерно так:

```text
https://github.com/USERNAME/python-course-surname.git
```

---

## 4. Клонирование репозитория

Перейдите в папку, где будут находиться учебные проекты.

Например:

```bash
cd Documents
```

Склонируйте репозиторий:

```bash
git clone https://github.com/USERNAME/python-course-surname.git
```

Замените `USERNAME` на своё имя пользователя GitHub.

Перейдите в папку проекта:

```bash
cd python-course-surname
```

Проверьте состояние репозитория:

```bash
git status
```

Если репозиторий пустой, Git сообщит, что коммитов пока нет.

---

## 5. Создание первого файла

Создайте файл `README.md`.

В Linux и macOS:

```bash
touch README.md
```

В Git Bash на Windows:

```bash
touch README.md
```

Откройте файл в редакторе и добавьте, например:

```md
# Основы программирования на Python

Учебный репозиторий студента НИУ ВШЭ.
```

Сохраните файл.

---

## 6. Добавление изменений

Посмотрите состояние репозитория:

```bash
git status
```

Добавьте все изменённые файлы:

```bash
git add .
```

Или добавьте только один файл:

```bash
git add README.md
```

Снова проверьте состояние:

```bash
git status
```

Файл должен появиться в разделе `Changes to be committed`.

---

## 7. Создание коммита

Коммит — сохранённая версия изменений с описанием.

Создайте первый коммит:

```bash
git commit -m "Add README"
```

Сообщение после `-m` должно кратко описывать сделанные изменения.

Примеры:

```bash
git commit -m "Add first solution"
git commit -m "Implement task 1"
git commit -m "Fix tests"
```

---

## 8. Отправка коммита на GitHub

Отправьте изменения в удалённый репозиторий:

```bash
git push
```

Если Git просит указать ветку, выполните:

```bash
git push -u origin main
```

После этого обновите страницу репозитория на GitHub. Файл `README.md` и первый коммит должны появиться в репозитории.

---

## 9. Рабочий цикл

После изменения файлов используйте последовательность:

```bash
git status
git add .
git commit -m "Describe changes"
git push
```

Пример:

```bash
git add .
git commit -m "Implement seminar task"
git push
```

---

## 10. Основные команды

| Команда | Назначение |
| --- | --- |
| `git --version` | Проверить установку Git |
| `git config --global ...` | Настроить Git |
| `git clone URL` | Скопировать репозиторий на компьютер |
| `git status` | Посмотреть состояние файлов |
| `git add .` | Подготовить все изменения к коммиту |
| `git commit -m "..."` | Создать коммит |
| `git push` | Отправить коммиты на GitHub |

---

## Важно

- Перед `git commit` проверьте результат команды `git status`.
- Не загружайте в репозиторий пароли, токены, ключи и другие секреты.
- Коммит создаётся локально, а `git push` отправляет его на GitHub.
- `git add` не создаёт коммит — он только подготавливает файлы.
