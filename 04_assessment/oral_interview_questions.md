## Блок 1. Словари (`dict`)

1. **(Б) Чем обращение `d[key]` отличается от `d.get(key, default)`? Когда лучше выбрать каждый вариант?**
   - *Ожидаемый ответ:* `d[key]` выбрасывает `KeyError`, если ключа нет (удобно, когда отсутствие ключа — это ошибка в данных, которую нельзя замалчивать). `d.get(key, default)` возвращает `default` (по умолчанию `None`) без исключения — удобно при подсчёте частот и чтении необязательных полей.
2. **(Б) Почему список `[1, 2]` нельзя сделать ключом словаря, а кортеж `(1, 2)` — можно?**
   - *Ожидаемый ответ:* Словарь хранит ключи в хеш-таблице. Ключ обязан быть хешируемым (`hashable`), чтобы его хеш не менялся со временем. Список изменяем (`mutable`), поэтому не имеет хеша (`TypeError: unhashable type: 'list'`). Кортеж из неизменяемых элементов неизменяем и хешируем.
3. **(Б) Что проверяет оператор `x in d` для словаря `d` и насколько быстро он работает?**
   - *Ожидаемый ответ:* Проверяет наличие `x` среди **ключей** (а не значений!) словаря в среднем за $O(1)$ благодаря хеш-таблице (в отличие от списка, где поиск занимает $O(n)$).
4. **(П) Что произойдёт, если сделать кортеж `([1, 2], 3)` ключом словаря?**
   - *Ожидаемый ответ:* Возникнет `TypeError`, так как кортеж хешируем только тогда, когда хешируемы **все** его вложенные элементы, а внутри него лежит изменяемый список.
5. **(П) Почему нельзя удалять ключи из словаря прямо внутри цикла `for k in d:` и как сделать это безопасно?**
   - *Ожидаемый ответ:* Изменение размера хеш-таблицы во время итерации ломает внутренний итератор и вызывает `RuntimeError: dictionary changed size during iteration`. Безопасно: итерироваться по копии списка ключей `for k in list(d.keys()):` либо собрать новый словарь через генератор `{k: v for k, v in d.items() if ...}`.

## Блок 2. Функции (`def`)

1. **(Б) В чём принципиальная разница между `print()` и `return` внутри функции? Что вернёт функция без `return`?**
   - *Ожидаемый ответ:* `print()` только выводит текст в консоль и не передаёт данные дальше по программе; `return` завершает вызов функции и возвращает объект в точку вызова. Функция без `return` (или с пустым `return`) всегда возвращает `None`.
2. **(Б) Что означают записи `*args` и `**kwargs` в заголовке функции? Какие типы данных они образуют внутри функции?**
   - *Ожидаемый ответ:* `*args` собирает произвольное число позиционных аргументов в кортеж (`tuple`), а `**kwargs` собирает произвольное число именованных аргументов в словарь (`dict`).
3. **(П) Объясните классическую ловушку `def add(x, items=[]):`. Когда именно создаётся список `items` и как исправить функцию?**
   - *Ожидаемый ответ:* Значения по умолчанию вычисляются **один раз** в момент выполнения инструкции `def` (создания объекта функции), поэтому один и тот же список переиспользуется между всеми вызовами. Правильный паттерн: `items=None` и внутри тела `if items is None: items = []`.
4. **(П) Как Python ищет имя переменной при обращении к ней внутри функции?**
   - *Ожидаемый ответ:* По правилу областей видимости **LEGB**: сначала локальная область функции (`Local`), затем объемлющие функции (`Enclosing`), глобальная область модуля (`Global`) и встроенные имена Python (`Built-in`). Присваивание `x = ...` внутри функции по умолчанию создаёт локальную переменную.

## Блок 3. Обработка ошибок (`try / except / raise`)

1. **(Б) Чем синтаксическая ошибка (`SyntaxError`) отличается от исключения во время выполнения (`ValueError`, `ZeroDivisionError`)?**
   - *Ожидаемый ответ:* `SyntaxError` обнаруживается парсером Python ещё до запуска кода (нарушена грамматика языка). Исключения времени выполнения возникают уже при работе синтаксически верного кода на конкретных данных и могут быть перехвачены блоком `try / except`.
2. **(Б) В каком случае выполняются блоки `else` и `finally` в конструкции `try / except / else / finally`?**
   - *Ожидаемый ответ:* `else` выполняется только тогда, когда в блоке `try` **не возникло** исключений. `finally` выполняется **всегда** (и при успехе, и при ошибке, и даже при `return` внутри `try`), поэтому используется для гарантированного освобождения ресурсов.
3. **(П) Почему запись «голого» `except:` (или `except Exception: pass`) считается опасным антипаттерном?**
   - *Ожидаемый ответ:* Голый `except:` перехватывает вообще всё, включая системные `KeyboardInterrupt` (`Ctrl+C`), `SystemExit`, а также опечатки программиста в именах переменных (`NameError`, `AttributeError`). В результате баги тихо маскируются под «штатную обработку», и отладка превращается в кошмар.
4. **(П) Когда в собственной функции стоит возвращать `None`, а когда — выбрасывать исключение через `raise ValueError(...)`?**
   - *Ожидаемый ответ:* `None` уместен, когда «ничего не найдено» — нормальный ожидаемый исход (например, поиск по ключу). `raise ValueError` нужен при нарушении контракта функции (например, передан отрицательный возраст или скидка 150%), чтобы вызывающий код не продолжал вычисления с некорректными данными.

## Блок 4. Модули и импорты (`import`)

1. **(Б) Чем `import math` отличается от `from math import sqrt` и почему не рекомендуется писать `from math import *`?**
   - *Ожидаемый ответ:* `import math` загружает модуль в отдельное пространство имён (`math.sqrt`), а `from math import sqrt` приносит конкретное имя в текущую область. `from ... import *` засоряет глобальное пространство десятками неизвестных имён и может незаметно перезаписать ваши функции или импорты из других библиотек (например, `math.sin` vs `numpy.sin`).
2. **(Б) Зачем в конце Python-файлов пишут `if __name__ == "__main__":`?**
   - *Ожидаемый ответ:* При прямом запуске файла (`python script.py`) интерпретатор присваивает его переменной `__name__` строку `"__main__"`, а при импорте этого файла из другого модуля — имя файла (`"script"`). Проверка позволяет запускать тесты или демо-код при прямом запуске, не вызывая их побочно при импорте функций модуля.

## Блок 5. Основы ООП (`class`)

1. **(Б) Что такое класс, что такое экземпляр (объект) класса и зачем в методах первым параметром пишется `self`?**
   - *Ожидаемый ответ:* Класс — это шаблон (тип данных), описывающий атрибуты и методы; экземпляр — конкретный объект, созданный по этому шаблону в памяти. `self` — ссылка на конкретный экземпляр, у которого вызвали метод (`obj.method(x)` фактически передаётся как `Class.method(obj, x)`).
2. **(Б) Для чего нужны специальные методы `__init__` и `__str__`? Что должен возвращать `__str__`?**
   - *Ожидаемый ответ:* `__init__` инициализирует атрибуты только что созданного объекта. `__str__` определяет человекочитаемое строковое представление объекта для `print(obj)` и `str(obj)` и обязан возвращать объект типа `str` (при возврате другого типа возникнет `TypeError`).
3. **(П) В чём разница между атрибутом класса и атрибутом экземпляра? Когда атрибут класса опасен?**
   - *Ожидаемый ответ:* Атрибут класса объявлен прямо в теле `class` и разделяется всеми экземплярами; атрибут экземпляра создаётся через `self.attr = ...` в `__init__` и индивидуален у каждого объекта. Если сделать атрибутом класса изменяемый объект (`items = []`), мутация через один экземпляр изменит состояние всех остальных объектов класса.

## Блок 6. Библиотека `pandas`

1. **(Б) Чем `pd.Series` отличается от `pd.DataFrame`? Что вернёт `df["col"]`, а что `df[["col"]]`?**
   - *Ожидаемый ответ:* `Series` — одномерный индексированный столбец, `DataFrame` — двумерная таблица из нескольких столбцов `Series`. `df["col"]` возвращает `Series`, а `df[["col"]]` (список имён) — одностолбцовый `DataFrame`.
2. **(Б) Почему при фильтрации `df[(df["a"] > 0) & (df["b"] < 10)]` нельзя написать `and` вместо `&` и нельзя опустить круглые скобки?**
   - *Ожидаемый ответ:* Оператор `and` в Python пытается привести весь столбец `Series` к одному `bool`, что неоднозначно и вызывает `ValueError`. Оператор `&` выполняет поэлементное логическое «И» для двух булевых столбцов, но у `&` приоритет выше, чем у `>` и `<`, поэтому без скобок Python попытается вычислить `0 & df["b"]`.
3. **(П) Почему в `pandas` векторные операции (`df["a"] * df["b"]`) работают на порядки быстрее цикла `for` по строкам?**
   - *Ожидаемый ответ:* Столбцы `pandas` опираются на типизированные массивы в непрерывной памяти (`NumPy`), и векторные операции выполняются в скомпилированном C-коде без накладных расходов интерпретатора Python на проверку типов и создание объектов на каждой строке.
4. **(П) Как работает связка `df.groupby("city")["amount"].agg(["count", "mean"])` и чем `count()` отличается от `size` при наличии пропусков `NaN`?**
   - *Ожидаемый ответ:* Реализует схему *Split–Apply–Combine*: разбивает строки по уникальным городам, считает агрегаты и собирает сводную таблицу. `count()` считает только **непустые** (`non-NaN`) значения в столбце, а `size` — общее число строк в группе вместе с `NaN`.

## Блок 7. Визуализация (`matplotlib` и `seaborn`)

1. **(Б) В чём соотношение между `matplotlib` и `seaborn`? Когда удобнее `seaborn`?**
   - *Ожидаемый ответ:* `seaborn` построен поверх `matplotlib`: он напрямую принимает `DataFrame` и названия столбцов (`x=`, `y=`, `hue=`), автоматически строит легенды и агрегации, а тонкая доводка осей, заголовков и сохранение файла выполняются методами объекта `Axes`/`Figure` из `matplotlib`.
2. **(Б) Какой график вы выберете для: а) распределения зарплат; б) связи площади квартиры и цены; в) динамики курса валюты по дням; г) сравнения медиан и выбросов чека по 4 городам?**
   - *Ожидаемый ответ:* а) гистограмма `histplot`; б) диаграмма рассеяния `scatterplot`; в) линейный график `plot` / `lineplot`; г) `boxplot`.
3. **(П) Почему гистограмма (`hist`) и столбчатая диаграмма (`bar`) — это разные графики, хотя оба рисуют прямоугольники?**
   - *Ожидаемый ответ:* `bar` сравнивает дискретные **категории** (высота — агрегат по категории, порядок столбцов можно менять). `hist` разбивает ось **непрерывной числовой переменной** на интервалы (`bins`) и показывает плотность/частоту попадания наблюдений в каждый интервал.

## Блок 8. Веб-приложение на `Flask` и веб-парсинг

1. **(Б) Как работает декоратор `@app.route("/user/<int:uid>")` во `Flask` и чем параметр пути отличается от query-параметра `request.args`?**
   - *Ожидаемый ответ:* Декоратор регистрирует функцию-обработчик для заданного шаблона URL и автоматически передаёт `uid` типа `int` аргументом функции (при нечисловом значении в URL сам вернёт `404`). Параметр пути — обязательная часть адреса ресурса (`/user/5`), а `request.args` — необязательные параметры фильтрации/сортировки после `?` (`/users?role=admin&page=2`).
2. **(Б) Зачем в веб-API используют `jsonify(...)` и возвращают HTTP-коды `200`, `400`, `404` вместо того, чтобы всегда возвращать текст со статусом `200`?**
   - *Ожидаемый ответ:* `jsonify` сериализует структуру в валидный JSON и выставляет заголовок `Content-Type: application/json`, чтобы фронтенд или другой сервис мог надёжно распарсить ответ, а стандартные HTTP-коды позволяют клиенту сразу отличить успех (`200`) от ошибки клиента (`400 Bad Request`, `404 Not Found`).
3. **(Б) Чем отличаются `soup.find()` и `soup.find_all()` в `BeautifulSoup`? Что вернёт каждый из них, если совпадений нет?**
   - *Ожидаемый ответ:* `find()` возвращает первый найденный объект `Tag` или `None`. `find_all()` возвращает список всех совпавших тегов или пустой список `[]`.
4. **(П) В браузере вы видите цены товаров на сайте, но `requests.get(url)` + `BeautifulSoup` возвращают пустой список карточек. Почему так бывает и что делать?**
   - *Ожидаемый ответ:* `requests.get` скачивает только исходный HTML-документ и **не выполняет JavaScript**. Если сайт (SPA на React/Vue) подгружает товары после загрузки страницы отдельным запросом, нужно открыть вкладку *Network -> Fetch/XHR* в DevTools и посмотреть, к какому внутреннему JSON API обращается страница (либо использовать браузерную автоматизацию вроде Playwright, если открытого JSON нет и правила сайта это допускают).
5. **(П) Назовите три технических приёма, которые делают ваш парсер надёжным и этичным.**
   - *Ожидаемый ответ:* 1) Соблюдение `robots.txt` и пауз `time.sleep` между запросами; 2) Обязательный `timeout` и обработка `requests.RequestException`, чтобы скрипт не зависал; 3) Изоляция разбора каждой карточки в `try / except` с сохранением промежуточных результатов на диск.

## Блок 9. Мини-кейсы «Code Review» для устного разбора (покажите студенту код)

### Кейс 1
```python
def load_prices(items):
    res = {}
    for line in items:
        try:
            name, price = line.split(":")
            res[name] = float(price)
        except:
            pass
    return res
```
*Вопросы студенту:* Что делает функция? Назовите минимум две проблемы в блоке `except:` и как вы бы переписали её чисто?  
*(Подсказка преподавателю: голый `except:` проглатывает `KeyboardInterrupt`/`AttributeError`; нужно ловить `ValueError`, обрезать пробелы `.strip()`, а при необходимости вести счётчик отброшенных строк).*

### Кейс 2
```python
@app.route("/avg")
def avg_price():
    df = pd.read_csv("big_sales.csv")
    city = request.args["city"]
    sub = df[df["city"] == city]
    return sub["price"].mean()
```
*Вопросы студенту:* Найдите **четыре** потенциальные проблемы в этом `Flask`-маршруте при реальных запросах!  
*(Подсказка преподавателю: 1) `request.args["city"]` упадёт с `400 BadRequestKeyError`, если `?city=` не передан — лучше `.get()`; 2) если города нет в таблице, `mean()` вернёт `NaN`; 3) возврат `float` напрямую из маршрута `Flask` вызовет `TypeError` — нужен `jsonify`; 4) чтение большого CSV с диска на каждый HTTP-запрос неэффективно — таблицу стоит загрузить один раз при старте).*
